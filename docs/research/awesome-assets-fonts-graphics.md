# Awesome Assets, Fonts & Graphics — GH Pages Vetting

> Slice: `awesome-fonts` + `awesome-icons` + `awesome-design` + `awesome game assets` → graphics polish for zero-build GH Pages (vanilla ES modules, 960×600 canvas, no bundler, jsDelivr/cdnjs/unpkg single-file only).

## Methodology

- **Date:** 2026-08-27. Queries (limit 5 each, top by stars):
  - `site:github.com awesome fonts` → **brabadu/awesome-fonts** (2,064 ★, CC0 list) — curated font collections + programming fonts section.
  - `site:github.com awesome icons` → **vkarampinis/awesome-icons** (1,556 ★, CC0 list) — 50+ generic icon sets + archives/tools; references Font Awesome, Lucide, Phosphor, Tabler, Bootstrap Icons, etc.
  - `site:github.com awesome design` → **gztchan/awesome-design** (17,455 ★) — stock / color / icon-logo / typography sections (Google Fonts, Fontshare, Material Icons, Game Icons, etc.).
  - `site:github.com awesome game assets` → **ellisonleao/magictools** (17,204 ★, MIT) — Graphics → Assets/Placeholders section lists **Kenney Assets, OpenGameArt, game-icons.net, GameIcon.net, Poly Pizza, Quaternius**, plus texture/sprite tooling; also referenced **skywind3000/awesome-gamedev** and **HotpotDesign/Game-Assets-And-Resources** as secondary cross-check.
- **Filter:** Only visual assets (fonts, icon sprites, texture/sprite assets). Sound-free. Skipped any entry requiring API key, commercial license, or NFT-gated paywall. Every candidate must be includable as a single static file or `<link>` on GH Pages (no npm build).
- **Inclusion Checklist per candidate:** License | CORS (`*`) | Keyless | ToS allows anonymous client fan-out | GH Pages compat (single file via CDN, no build) | Zero cost. Each cell cites primary source (repo `LICENSE`/`OFL.txt`, README, Google Fonts specimen page, jsDelivr CDN page, project ToS/FAQ).

> Stack context: current HUD/controls use `ui-monospace, Menlo, Consolas, monospace` (`index.html:12`, `js/render.js:6`, `CONFIG.arena.starCount` procedural stars). Arena is pure Canvas 2D — no WebGL — so winning upgrades are those that stay CSS/static-asset and add zero JS weight.

## Synthesis — Biggest Visual Lift Without Adding JS Weight

**Current baseline:** `index.html` uses system `ui-monospace` and a procedurally generated white-dot `stars` array (`js/render.js:9–13`). Asteroids/ship are stroked Canvas 2D paths (`renderArena`), particles are small squares/circles. The palette is dark space (`#05070c` / `#0b0e14`) with cyan accent (`#39d0ff`). The bottleneck for "polish" is not more JavaScript — it's font rendering and static textures that can be added with **zero per-frame cost**.

### Recommended static-only upgrade path (3 variants modular by `?variant=`)

The table suggests two orthogonal levers: **HUD typography** and **arena texture**. Either alone is a noticeable lift; together they change the feel without touching the rAF loop.

#### 1. HUD font upgrade — pick one (all PASS, single `<link>`)

- **Highest recommendation: JetBrains Mono (400 + 600) via Google Fonts.**
  - Why: crisp at the current `13px/1.4` HUD size, excellent legibility for `renderHUD` telemetry (`pop`, `world`, `brainIdx`) and `#speedValue`/`#speedEff`. Keeps the monospace HUD contract but removes the "system font fallback" mush on Windows/Linux. Add with one line: `<link href="https://fonts.googleapis.com/css2?family=JetBrains+Mono:wght@400;700&display=swap" rel="stylesheet">` and change `FONT` in `render.js:6` to `'JetBrains Mono, ui-monospace, …'`. Falls back cleanly if offline. Weight 400 for body HUD, 700 for generation counter.
  - Runner-up: **Recursive Mono (`MONO=1, CASL=0, wght 400→700`)**. Use if the prototype wants variable-font contrast (e.g., slanted `slnt` for paused state, heavier `wght` for best-fitness highlight) without extra requests. Larger file but still one CSS request when subset to `latin` + two weights. Ideal for the `?variant=recursive` throwaway prototype where HUD typography is the experiment.
  - Niche: **IBM Plex Mono** if the art direction leans "NASA console"; **Space Mono** if it leans "arcade cabinet". Both are valid single-link swaps for a third variant.

> Variable-font note: Recursive's `MONO` axis is the win — it lets us keep the strict monospace grid for chart/net axis labels while relaxing to quasi-proportional for any future heading, all from one woff2. JetBrains Mono's variable build offers `wght` only, which is sufficient for HUD hierarchy if the monospace vibe must stay absolute.

#### 2. Icon sprite for DOM chrome — one single file (optional, still zero canvas cost)

- **Pick Lucide (ISC) or Phosphor `regular` (MIT) — not both.**
  - Lucide is lighter (fewer glyphs, 1 px stroke matches canvas `lineWidth: 1`). Good for the four control buttons only.
  - Phosphor `regular` has better game semantics (`planet`, `crosshair`, `rocket`) if the prototype also badges asteroid types in the HUD. Both are available as a **single CSS or single UMD JS** on jsDelivr, so GH Pages inclusion is one `<link>` or one `<script>` with no bundler. For the strictest "no JS weight" variant, use the **CSS-only** include and restrict icons to DOM chrome — never inject icons into the canvas per-frame.
  - Bootstrap Icons is the safe "we need everything" fallback, but its larger payload makes it the weakest recommendation for this game.

#### 3. Arena texture — one vendored PNG (biggest arena lift, still static)

- **Kenney `Space Shooter Redux` / `Background Elements` (CC0) + game-icons.net SVG stamps (CC BY 3.0) — vendor 1–2 files into `assets/`.**
  - **Starfield:** replace/augment the procedural `stars` dots with a tiled 512×512 `starfield.png` (Kenney, CC0) drawn once per frame as a `drawImage` background or CSS `background-image` on `#arena`. This is visually richer (subtle color variance, nebula flecks) than white dots and costs one `drawImage` (cached `HTMLImageElement`), not per-star `arc` calls. Keep the procedural `stars` array as fallback when the image hasn't loaded.
  - **Asteroid texture:** optionally stamp a cratered asteroid SVG from game-icons.net (CC BY 3.0, e.g., `asteroid` / `stone-sphere`) as a clipped `drawImage` inside each asteroid polygon. Adds perceived detail without changing physics — still stroke the outline for gameplay readability.
  - Attribution: Kenney CC0 needs none; game-icons.net CC BY 3.0 needs one comment line (`<!-- Icons: game-icons.net CC BY 3.0 — Delapouite et al. -->`) and a matching line in `README.md` credits.

**What to skip and why:**
- **OpenGameArt** (`NEEDS_CHECK`) — too mixed-licensed for a zero-friction GH Pages fan-out; use only if a specific CC0 asset is hand-vetted. Kenney already covers the CC0 need with blanket permission.
- Any asset requiring an API key, commercial license, or server-side generation (e.g., paid texture APIs, NFT-gated sprites) — excluded by the brief and by the Inclusion Checklist.

### Concrete `?variant=` mapping for the prototype phase

| Variant param | Font | Icons | Texture | JS weight delta |
|---------------|------|-------|---------|-----------------|
| `?variant=jetbrains` (recommended default) | JetBrains Mono | none or Lucide CSS | Kenney starfield PNG (single `drawImage`) | ~0 JS (1 CSS link + 1 PNG) |
| `?variant=recursive` | Recursive `MONO=1` | Phosphor `regular` CSS | game-icons.net asteroid stamp + Kenney starfield | ~0 JS (1 CSS link + 1–2 static images) |
| `?variant=plex` | IBM Plex Mono | Bootstrap Icons SVG sprite | none (procedural stars only, but thicker HUD weight) | ~0 JS (1 CSS link) |

All three stay **static-only**: no bundler, no npm build, no runtime texture generation, CORS-safe, keyless, zero-cost, and deployable as-is to GH Pages (`index.html` + `js/*.js` + `assets/*.png`/`*.svg`).
