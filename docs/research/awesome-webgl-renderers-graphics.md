## Synthesis — What to Use for `?variant=` Throwaway Prototypes

### The 960×600 toroidal seam problem dominates the decision

`render.js:seamCopies(x,y,r)` currently duplicates each entity at `±W/±H` when `x±r` or `y±r` crosses an edge. Any replacer must keep that O(1)-per-entity duplication — which is trivial for **scene-graph libs** (Two.js `Group`, Pixi `Container`, Kontra `Sprite`, LittleJS `EngineObject`) by instantiating 4 views offset, and manual for **shader libs** (regl) by issuing 4 draw calls. Candidates that own the loop (Phaser, PlayCanvas, Kaboom to a lesser extent) fight this: they'd reimplement wrap internally, losing the clean `seamCopies` hook.

### Recommendation — modular `?variant=` plan

1. **Keep vanilla as `?variant=vanilla` (0 KB).** The existing `ArenaRenderer` façade already owns HiDPI + `seamCopies` + throttling. Deleting/replacing it scatters ownership — the class is the seam to swap. Vanilla proves the floor: Canvas `shadowColor/shadowBlur` already gives soft glow for bullets/ship at zero bytes.

2. **For the 3 throwaway prototypes (per the broader research brief):**
   - **Variant A — *Vector Bloom* (regl ~9 KB).** Keep `render.js` structure, swap inner draw to regl FBO bloom: draw asteroids/ship/bullets as signed-distance polygons, then horizontal + vertical blur passes → additive. Demonstrates that **15 KB of shader** beats 50 KB of library for bloom. Keeps seam copies as uniform offsets. Fallback: if WebGL unavailable, fall back to vanilla `ctx` (regl has no Canvas fallback — guard with `try { createREGL } catch`).
   - **Variant B — *Scene Graph* (Two.js ~15 KB or Kontra ~5 KB).** Replace immediate `ctx` draws with retained `Two.Path` / `Kontra.Sprite` nodes. Gains: declarative asteroid shapes, easy `starfield` as batched circles, particles via groups. Pick Two.js if you want WebGL auto-batch; Kontra if you want minimal bytes and pools. Both preserve `seamCopies` by cloning groups.
   - **Variant C — *Full Filter* (PixiJS ~45 KB, gated).** Only if a variant must showcase **drop shadows + multi-pass bloom + blend-mode thrusters**. Load Pixi via importmap (`"pixi.js": "https://cdn.jsdelivr.net/npm/pixi.js@7.4.2/+esm"`) so most users never pay the cost. Use `ParticleContainer` for bullets, `BlurFilter` for bloom, `DropShadowFilter` for asteroids. Accept that this is the ceiling — it justifies vanilla vs. 40 KB vs. 50 KB trade-off.

3. **Skip for `?variant=`:** PlayCanvas and Phaser — they violate the "lightweight helper, no build, no rewrite" contract. They'd be the right choice for a **new** game, not for augmenting a 960×600 toroidal arena that must stay evolvable at 10,000× sim speed. If either is tried, it should be a **separate branch**, not a query-param toggle.

### Bundle size vs visual gain for GH Pages

GH Pages serves over jsDelivr's edge with `cache-control: immutable` for versioned URLs, so the marginal cost after first hit is near zero. The real cost is **first-paint bytes on slow mobile**:

- **0 KB → ~12 KB gz (Kontra):** 95th-percentile 3G still < 200 ms extra — negligible for a research demo. Gain is structural (pools), not visual.
- **0 KB → ~15 KB gz (Two.js) or 9 KB (regl):** sweet spot. Regl's bloom is visually disproportionate to its bytes — a 9 KB lib producing cinematic glow is the best *wow per byte* of the table.
- **0 KB → ~45 KB gz (PixiJS):** crosses the "is this still a tiny demo?" line — GH Pages can serve it, but it doubles the current JS payload (`js/*.js` ~30 KB uncompressed). Justifiable only for a filter-heavy showpiece; lazy-load behind `?variant=pixi` so the default stays vanilla.

**Bottom line:** For GH Pages static with no bundler, the **best modular helpers are Kontra (4 KB), regl (9 KB), and Two.js (15 KB)** — each is a single CDN file, `*` CORS, MIT, no key, and importable via `<script>` or importmap. PixiJS remains the **only** PASS option that gives true shader bloom in a scene graph without writing GLSL; reserve it for the heaviest variant.
